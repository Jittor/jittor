# Jittor 2.0 迁移说明

## 破坏性变更

### 移除了 Torch 运行时的私有别名

`jittor._torch_leaf_params`、`_torch_retained`、`_torch_tensor_state`、
`_active_optimizers`、`_current_optimizer`、`_torch_shim_runtime_state` 和
`_transform_getitem_to_index_depth` 不再是运行时契约。独立模式与历史别名模式都把
张量记账放在 Runtime 拥有的状态里；激活状态通过
`jittor.compat.shim.activation_status()` 查询。

兼容层实现改用 `get_tensor_state()` / `latest_optimizer()` 和上下文局部的 getitem
作用域。**应用代码应该使用 Tensor 的梯度 API 和优化器实例，而不是私有注册表属性。**

### 张量语义：0 维结果、整数提升、以及一个不再原地的方法

有三处改动会改变现有**原生 Jittor** 代码算出来的结果，不只是改变它导入什么。
Torch 模式不受影响——兼容层把这些映射到 PyTorch 自己的语义，而这正是它们改成
现在这样的原因。

**索引到标量现在得到 0 维 Var。** `a[1, 2]` 的 `ndim == 0`，而 1.x 会把空形状补成
`(1,)`。依赖那个补齐的代码——`a[i, j].shape[0]`，或者把单个元素拼起来——现在必须
显式写出来。这同时也是 NumPy 兼容的类型提升得以成立的前提：`float64 * float32`
现在是 `float64`，不再被静默收窄。

**整数提升按种类与位宽，不再按字节数。** `uint8(200) + int8(1)` 是 `int16`
（值为 201，不是回绕后的 8 位结果），`uint8 * (1/255.)` 是 `float32`。1.x 取两者
字节数的较大值再把符号位或起来，这会把混合符号的运算变成一次**静默回绕**。

**`Var.scatter` 返回新 Var。** 它在 1.x 里是原地的。`x.scatter(...)` 不再改动 `x`；
请使用返回值，或用 `x.scatter_(...)` 这个原地写法。

### 26 个靠启发式生成的 `x.foo_()` 原地别名被删除

1.x 会给任何"第一个参数看起来像张量"的函数生成一个原地方法，一共造出 85 个别名，
其中若干**根本不是原地的**：`isnan_`、`norm_`、`sort_` 和 `tolist_` 返回的是非 Var
值，名字却承诺了修改。

生成的这一批被一份**声明式的 48 个方法白名单**取代。消失的拼写里最可能出现在现有
代码中的是：`exp_`、`log_`、`sin_`、`cos_`、`tanh_`、`relu_`、`div_`、`neg_`、
`round_`、`floor_`、`ceil_`、`sum_`、`mean_`、`max_`、`min_`、`argmax_`、`sort_`、
`norm_`、`isnan_`、`tolist_`、`matmul_`、`reshape_`、`all_`、`any_`、`float_`、`int_`。
改写成 `x.assign(x.exp())`——这正是原来生成的别名所做的事。

`all_` 和 `any_` 还有第二个原因：它们是**归约原语的名字**，不是修改型方法，末尾的
下划线让人读成后者。

**Torch 模式保留全部这些**——`torch.Tensor.exp_()` 可用且原地生效——所以下游
PyTorch 代码不需要改动。注意兼容层通过 `__getattr__` 提供它们，因此 `hasattr` 会
报 `False`，但调用是成功的。

### 过去被接受然后忽略的参数，现在会警告或报错

1.x 接受了一批 PyTorch 形状的关键字参数却什么也不做。现在传入非默认值会警告或报错，
而不是**返回一个在与调用者所要求的不同设置下算出来的结果**。

涉及：激活函数的 `inplace=`、`instance_norm` 的 running-stats 参数、ResNet 的
`zero_init_residual`、`svd` 的 `compute_uv`/`driver`、`inv_ex` 的 `check_errors`、
`ctc_loss` 的 `zero_infinity`、`topk` 的 `sorted`、`sort` 的 `stable`、Kaiming
初始化器的 `generator`、`DataLoader` 的 `pin_memory` 与 `persistent_workers`、
`vjp`/`jvp` 的 `strict`，以及 `fftfreq` 的 `dtype`/`device`。

`MaxPool3d(ceil_mode=True)` 的输出形状因同类原因发生变化：1.x 比 PyTorch 多产生一个
平面，因为它漏掉了"丢弃完全落在 padding 里的窗口"这条修正。`MaxUnpool3d` 的默认
`output_size` 由它推出，所以两者往返仍然对得上。

### 命名空间是声明出来的，不是附带产生的

根包和 `jittor.nn` 现在导出声明式的 `__all__`。仅仅因为 star import 而存在的名字
消失了：最可能出现在现有代码里的是 `jt.np`（请直接用 `numpy`），并且
`dir(jt.nn)` 不再包含任何下划线开头的条目。

Flag 按**生命周期**拆分：`jt.config` 是启动时决定内容的只读快照，`jt.runtime` 放
运行期间可以改变的开关。`jt.flags` 仍然可用。

### 用户错误现在是可捕获的异常

非法的形状、dtype 和索引会抛 Python 异常，而不是调用 `LOGf` 直接中止进程。原本通过
避开这些情况来防御的代码照常工作；依赖"进程会死"的代码不再成立。

**内部不变量的违反仍然是断言**——这个区分正是本次改动的意义所在：**从 Jittor 调用
里逃出来的异常，现在永远是在陈述调用者输入的问题。**

### 原生 Jittor 与 Torch 兼容分别激活

普通的 `import jittor as jt` 保持原生 Jittor 语义，**不再占用顶层 `torch` 命名空间**。
Torch 模式由已部署的 shim、`JITTOR_TORCH_SHIM=1`、显式调用
`jittor.compat.shim.activate()`，或历史的 `import jittor.torch_compat` 路径选中。
单纯写一个 `import jittor as torch` 的本地别名**不再改变进程模式**。

这恢复了 2.0 之前的原生契约，例如 `Var.data` 返回共享的 NumPy 视图。Torch 模式下
`Tensor.data` 仍是 detach 的 Tensor 别名，其原地更新留在当前设备上。

**应用不得在模型开始执行之后再从原生模式切换到 Torch 模式**，因为兼容安装会改变
进程级的类 API。

### Torch 兼容不再替换 Jittor 的包版本号

`jittor.__version__` 现在**始终**报告已安装的 Jittor 发行版本（本发布线为
`1.3.11.0`），即使用的是部署的 Torch 入口、`torch is jittor` 时也一样。需要被模拟的
PyTorch API 级别时，请用 `jittor.__torch_version__` 或 `torch.version.__version__`，
两者当前都报告 `2.11.0`。

必需的 Torch 兼容安装器**总是**以具名的安装步骤失败，即使
`JITTOR_TORCH_STRICT_BOOTSTRAP` 被关闭。那个开关只控制可选的 shim 运行时引导，
**不能掩盖不完整的核心 API**。部署 CLI 的校验命令通过 `torch.__torch_version__`
和 `torch.version.__version__` 报告 Torch API 版本，而不是同模块入口以
`torch.__version__` 暴露的 Jittor 后端版本。

### `jittor.vcompiler` 退役

Jittor 2.0 移除了实验性的 `jittor.vcompiler` 包及其 `build()` 装饰器。导入那个包会
**作为副作用**编译一个私有的 C++ 静态图扩展，而该 API 在仓库内没有消费者，也没有
稳定的兼容契约。源码 checkout 和已安装的 wheel 现在都报告 `jittor.vcompiler` 无模块
规格。

它那个带缓存的静态图装饰器**没有直接替代品**。模型代码请使用正常的 Jittor 图执行。
需要自定义算子的扩展作者应使用维护中的 `jittor.compile_custom_op` 或
`jittor.compile_custom_ops` 接口，并在每个受支持的后端上显式测试前向与反向。

### 仅供仓库使用的内容移出 wheel

运维脚本、发布工具、示例和 notebook 现在位于顶层 `tools/` 和 `examples/`。它们仍在
源码发行物中，但**不再是运行时 wheel 的可导入成员**。已安装环境的校验用
`python -m jittor.selftest`。

`examples/notebooks/` 下的 MyST Markdown 是教程的规范来源。生成的 `.ipynb` 不再纳入
版本管理，也不随源码发行物分发；`python -m nox -s tutorials` 会在仓库外生成它们并
运行维护中的离线 CPU 冒烟集。

`jittor/extern/llvm` 下遗留的 Clang 对齐 pass 及其未被使用的
`jittor.compiler.compile_extern()` 构建钩子已被移除。该钩子运行时从未被调用，而保留
这个私有 LLVM 插件会让 Clang 启动依赖一个无人维护的编译器内部 ABI，对活跃的 JIT
路径毫无帮助。
