## Implemented boundaries

Serialization is now a package with separate portable, security, Torch archive
and safetensors owners. Restricted loading no longer probes legacy pickle with
an unrestricted loader, and explicitly rejects native-only fallback paths that
cannot enforce `weights_only=True`. Materialized views preserve their values;
this does not claim shared-storage alias preservation across serialization.

Autograd, library registration, distributions, factories, module hooks, FSDP
public helpers and vmap bind module-level implementations. Captured native
delegates belong to read-only installation state and participate in rollback.
Registered custom-op backward now receives detached floating outputs through
the native Function tape. vmap preserves genuine trailing singleton dimensions
after the native scalar migration. Placeholder APIs keep explicit unimplemented
metadata; moving their owner does not implement their missing behavior.

The independent namespace closes its native fallback after installation.
Declared mathematical delegates use stable objects and frontend scopes;
FFT/linalg publish owned public facades, excluding imported implementation
modules. Native runtime helpers remain behind the explicit owner boundary.
The final API manifest supplements family fidelity records and the generated
`fidelity_table()` report. Per-spelling records, rather than attributes on a
shared alias object, are authoritative. See the
[API ownership contract](../architecture/torch-api-ownership.md).

## File layout acceptance: 11.03

A read-only scan of 1175 implementation files across `python/jittor`,
`python/jittor_utils`, `compat`, `adapters`, `src` and `backends` found no file
over 1500 lines. It includes Python, C/C++, CUDA, headers, inline fragments,
assembly and shell implementation files; generated caches and vendored
third-party implementations are excluded. The largest is
`python/jittor/build/compiler.py`, 1472 lines.

The old tensor-ops/core-api facades delegate to domain packages. Torch nn/tensor
installers, FlashAttention and ACL builders have domain owners. C++
`src/codegen/op_compiler.cc` (1352 lines) and `src/codegen/opt/expr.cc` (1180)
remain individual translation units in their final domain; they were not split
into smaller TUs. Generated `python/jittor/__init__.pyi` is 9142 lines and is
regenerated by `tools/build/gen_pyi.py`; the size acceptance applies to maintained
implementations, not this generated declaration inventory. The unified Var/Op
graph and seven meta-operators remain intact.

## Still open: native placement and independent frontend

7.03 also remains partially implemented. The named-installer scan finds 73
entry points and five nested lifecycle/module-patch definitions, but misses
behavior defined inside type factories. `distribution_frontend.py` still nests
rsample policy, constructor argument adaptation and public property wrappers;
`nn_frontend.py` still nests Module call/assignment and constructor parameter
adoption. These are real implementation owners, not merely type identities.
Their migration and an audit of the remaining frontend type factories must
precede closing 7.03. This batch closes only 11.03: 22 open code/performance
records become 21, with nine hardware records still separate.

`KI-BACKEND-PLACEMENT-001` is a real CUDA failure: loading with
`map_location="cpu"` initially gives host storage, but a later operation can
move it and its result back to CUDA while the frontend still reports CPU.
Constructing the loaded Tensor explicitly on CPU alone does not fix execution
selection. The regression
`test_cuda_checkpoint_mapped_to_cpu_stays_on_cpu_for_subsequent_ops` is a strict
xfail, not a successful hardware check. 7.12 stays open until native tensor
placement, graph propagation, execution and frontend factory/to/load boundaries
agree. The native work is isolated from this Python owner batch and has not yet
passed runtime validation. NPU/HCCL/ROCm/Corex and multi-machine verification,
FSDP peak-memory performance and other remaining board tasks are not closed by
this report.
