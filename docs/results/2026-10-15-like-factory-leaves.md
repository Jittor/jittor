## Verified problem and repair

`empty_like` bypassed the shared factory option adapter. An omitted or explicitly
false `requires_grad` still produced a tensor requiring gradients. Explicit true
appeared to create a leaf but failed to publish its own gradient after backward.
`zeros_like`, `ones_like` and `full_like` exposed their internal broadcast/cast
graph when gradient recording was requested. Separately, explicit `dtype=None`
incorrectly used the global default dtype in `zeros_like` and `full_like`.

The repair keeps all option handling in `compat/torch/installers/factories.py`.
The existing empty allocator now delegates to the shared constructor adapter.
These four like factories detach the allocation's internal history before using
the existing requires-grad and leaf-registration path. Explicit `dtype=None`
keeps the input dtype. The API fidelity classification remains approximate;
passing the tested contiguous/strided options does not establish arbitrary
layout, pinned-memory, or memory-format support.
