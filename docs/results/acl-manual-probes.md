## 容量观察

原 `MAX_MODEL_RESULT.md` 记录：64 GB 910B3，使用 RMSNorm 的 GPT 风格模型，
词表 50257、batch 1、序列长度 512，执行一次 Adam 更新。

| 类型 | 参数量 | 原记录结果 |
| --- | --- | --- |
| fp32 | 1.6B | 完成，约 39 GB HBM |
| fp32 | 2.5B | 完成，接近容量上限 |
| fp32 | 3.6B | 内存不足 |
| bf16 | 2.5B | 优化器算子错误，不能归为内存不足 |

原文据此估算单卡全量微调上限 2.5–3B，另记录 Qwen3-8B bf16 LoRA 约 22 GB，
并推算约 20B 的 LoRA 上限与八卡数据并行约 8 倍吞吐。这些推算**不是实测边界**。
容量探针中未使用的 LoRA 分支没有把 adapter 接入前向，不能支撑 LoRA 容量结论，
现已移除该分支。数据并行复制模型，不合并显存；不能由此推断当前 bf16 支持或多卡吞吐。

## 数值观察

原 GPT-2 记录日期为 2026-06-22：2 层、4 个头、宽度 128、fp32，共用生成的权重与输入。

| 后端 | Loss | 总梯度 L2 | loss / 范数 / 最差参数范数相对误差 |
| --- | --- | --- | --- |
| PyTorch CPU | 6.237304 | 0.045244 | 参考 |
| Jittor CUDA（4090） | 6.237304 | 0.045244 | 7.6e-8 / 1.0e-7 / 2.8e-7 |
| Jittor ACL（910B3） | 6.237304 | 0.045244 | 7.6e-8 / 4.7e-6 / 4.4e-5 |

这是相对于 CPU 参考的**梯度范数**比较，不是同设备逐元素前向、反向验收。
范数相同不能排除梯度方向不同。旧比较器只打印差异，不会因参数缺失失败；迁移后的
比较器拒绝不完整或超容差的结果，配有不依赖硬件的回归测试。

Qwen3-0.6B 原记录的 argmax 均为 12095，top 5 均为
`[12095, 7407, 279, 1112, 30743]`，logit 范数分别为 1493.90（PyTorch CPU）和
1494.59（Jittor NPU）。原文还声称最大 logit 误差 0.0012、CUDA GPT-2 八步 loss
6.39 → 1.41，以及两个后端上的 `.pt` 读取。保存的探针仅输出摘要；缺少原产物与新的
可复现执行，不能将这些描述升级为当前的完整 logit、训练或序列化验收。
历史 `import jittor as torch` 是实现身份，不是现在推荐的 shim 用法。
