# verl v0.9.1 CPU 核心适配结论

- Status: Accepted for the measured CPU core scope
- Date: 2026-09-22
- Baseline commit: `a2ed9173583a25d3f3058405a9a50181783fbca3` 加本文所列工作树修复
- Owner: Jittor compatibility maintainers（生态清单推动人待登记）
- Review when: verl、Transformers 或 TensorDict 跨锁定版本，或范围扩大到 Ray worker、
  FSDP2、rollout、checkpoint、vLLM、CUDA/NPU

## 结论

verl `v0.9.1`（commit
`1876b06d0a3e4e71e06230be10af14492ca8a75b`）的轻量 CPU 核心范围已接入 Jittor 2.0：

- `verl`、`verl.protocol` 和 `verl.trainer.ppo.core_algos` 真实导入；
- 12 种上游 policy loss 完成注册；
- `DataProto` 的构造、CPU transfer、等分 chunk、tensor/non-tensor interleave repeat 通过；
- PPO clipped loss、三个指标及 `log_prob` backward 与官方 PyTorch 固定 oracle 相符；
- GRPO outcome advantage/returns 与官方 PyTorch 固定 oracle 相符；
- Transformers 5.9.0 正确识别兼容前端声明的 PyTorch API 版本 `2.11.0`，模型功能不再因
  Jittor 发行物版本 `1.3.11.0` 被关闭。
- 无下载构造的 tiny Qwen3（3,648 参数）完成 forward、causal-LM loss 和 backward；
  logits shape 为 `(1, 4, 32)`，14/14 个可训练参数都有梯度。

本次没有修改 verl 源码。分类为：verl 普通 Python 算法为 C2，Transformers 私有版本探测为
C3 optional adapter，aarch64 编译和 wheel 文件遗漏为 C4 build/core。覆盖 L0（导入）、
L1（DataProto 语义）和 L2（PPO/GRPO、tiny model 前向与梯度）。完整分布式训练和设备执行不在本次
已验收范围内。

## 数值结果

两侧运行同一个
[`test_verl_compat.py`](../../compat/tests/torch/test_verl_compat.py)。测试固定输入，不以 shim
输出生成期望值；期望值先在独立官方 PyTorch 环境得到，再硬编码进共同门禁。

| 检查 | 官方 PyTorch 2.12.0 | Jittor shim | 结果 |
| --- | --- | --- | --- |
| DataProto chunk/repeat/to | 通过 | 通过 | tensor 与 object array 完全相等 |
| PPO loss | `-0.0941485539` | 门限内相符 | `rtol=1e-6, atol=1e-7` |
| PPO clip fraction / KL / lower clip | `0.4 / 0.0799999908 / 0.0` | 门限内相符 | 通过 |
| PPO `log_prob` 梯度 | 固定 `2x3` oracle | 门限内相符 | `rtol=1e-6, atol=1e-7` |
| GRPO advantage/returns | 固定 `4x3` oracle | 门限内相符 | `rtol=1e-6, atol=1e-7` |
| 轻量核心回归 | 3 passed，4.097 s | 3 passed，13.907 s | 通过 |
| tiny Qwen3 smoke | 未用于数值 oracle | logits `(1,4,32)`；14/14 参数有梯度 | forward/backward 通过 |
| 含模型完整门禁 | 4 passed，5.032 s | 4 passed，18.076 s | 通过 |

墙钟包含解释器和框架初始化，只记录功能运行，不是性能结论。shim 的 namespace owner、激活
状态和 CPU device 被显式断言；oracle 显式断言真实 `torch._C` 且没有 shim 标记，排除了
自我对拍。

## 修复

1. `src/mem/mem_info.cc` 与 exec-plan C++ 测试在输出/比较原子计数前显式 `.load()`，修复
   GCC 10/aarch64 对 `std::atomic<int64>` 的重载歧义。
2. 为 `backends/cuda/kernels/cublas` 补 package marker，并增加结构门禁，避免 wheel 静默遗漏
   `lt_linear_cuda.py` 等 backend Python 模块。
3. distribution frontend 同时复制 `ModuleType` 实例和其子类的公开属性，恢复
   `torch.distributions.constraints.real/positive/interval/dependent_property`，使 TensorDict
   0.10.0 可真实导入。
4. Transformers optional adapter 支持严格锁定的 5.9.0；只把 `torch` 包探测映射到
   `torch.__torch_version__`，并保持布尔探测与版本探测的原始返回类型，同时继续阻止误探测
   原生 `torch_npu`。
5. 增加可选 verl 真实下游门禁；`JITTOR_REQUIRE_VERL=1` 会把缺包从 skip 提升为失败。

## 环境边界与未验证项

- `<Ascend-host>` 能看到 8 张 Ascend 910B3，但裸机只有 `/usr/local/Ascend/driver`，没有 CANN
  Toolkit；当前用户环境也没有 `torch_npu`。因此本次不能诚实声明 NPU worker 或训练通过。
- 裸机没有 `cmake`，Jittor 默认首次 batched matmul 会尝试构建可选 oneDNN。本次通过
  `JT_BUILD_USE_MKL=0` 使用通用 CPU kernel；这不是 verl 或 Torch API 缺陷。
- Ray actor、FSDP/FSDP2、分布式 collective、rollout engine、vLLM weight transfer、
  checkpoint 和完整 PPO step 未在当前 v0.9.1 环境复验。
- 没有测速度、峰值内存或显存；不能引用导入/测试墙钟作为性能结论。
- 历史报告记录过另一套 checkout 的 CUDA 四卡 FSDP2/tiny Qwen3 PPO，以及 910B3 上多种
  policy loss 的 `torch_npu` 对拍；由于上游版本、环境和 harness 不同，不计入本次验收。
