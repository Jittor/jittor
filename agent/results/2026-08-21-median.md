# Median 原生与 Torch 模式 CPU/CUDA 修复验证

- Status: CPU/CUDA verified; NPU/ROCm not verified
- Date: 2026-08-21
- Baseline: `c3750d82`
- Owner: misc and Torch compatibility maintainers
- Review when: median, argsort/sort, compatibility reductions, scalar rank, or
  backend selection changes

## Problem and fix

The native implementation built only `dim - 1` leading slices, so every nonzero
axis selected from the wrong dimension. It also unpacked `jt.argsort` as a native
`(indices, values)` tuple. Under Torch mode `jt.argsort` returns one indices Var:
most shapes raised while a leading extent of two silently unpacked two rows,
returned integer indices as median values, and produced zero input gradients.
Negative axes other than `-1` reached the core argsort operation unnormalized.

The native operation now normalizes and validates the axis, accepts either the
native tuple or Torch indices-only argsort result, gathers values when needed,
and selects with a full-rank slice. The Torch installer separately publishes
module and Tensor median forms: an axis reduction returns a `median(values,
indices)` tuple with int64 indices, while the no-axis form returns the selected
value. Both paths remain composed from Jittor sort/gather/indexing operations, so
gradients and accelerator residency are retained.

## Verification

The pre-fix Torch-mode reproduction covered `dim=None, 0, 1, 2, -1, -2` and both
`keepdim` values on a distinct `2 x 3 x 4` input. It reproduced an exception for
the global form, zero gradients and index-valued outputs for shape-dependent
"successful" cases, wrong output shapes, and core errors for other axes. An
independent PyTorch 2.12.1 CPU probe fixed the expected module/method return type,
values, indices, shapes, and gradient routing.

Environment: Python 3.11.15 for the explicit Torch shim and Python 3.12.13 with
independent PyTorch for the native CUDA process, CUDA 12.2, cuDNN 8, and RTX 4090.
CPU and CUDA runs used isolated state outside the repository; first JIT work was
serialized. CUDA tests assert accelerator residency and read complete forward and
gradient arrays.

The OpInfo second-order check remains explicitly skipped because median is a
piecewise selection and the underlying indexed scatter has no maintained
second-order contract. NPU and ROCm were unavailable. The global result still
uses Jittor's maintained one-element scalar representation (KI-SHAPE-001), and
the Torch `out=` overload is not implemented.

## Separate startup finding

The deployed-shim Python 3.11 environment could not be used as native CUDA
evidence. With CUDA enabled, plain `import jittor` imported
`jittor.compat.triton`, whose dependency chain imported the deployed top-level
`torch` placeholder and activated Torch mode despite `JITTOR_TORCH_SHIM=0`.
Import tracing and API-owner checks reproduced this semantic switch. Native CUDA
verification therefore used the Python 3.12 environment containing independent
binary PyTorch. The startup issue is tracked as KI-COMPAT-003 and is not treated
as a median failure.
