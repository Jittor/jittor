# Transformer Block GPU1 基线（2026-07-11）

## 口径

- 设备：RTX 4090，`CUDA_VISIBLE_DEVICES=1`；Jittor 使用 `conda jt311` 当前未提交工作树，PyTorch oracle 为 `/home/zy/rt_venv` 的 `torch 2.12.1+cu130`。
- 负载：`B=2, S=128, H=768, heads=12` 的 pre-norm Transformer block，包含 QKV/SDPA/output projection、残差、LayerNorm 和 4x GELU MLP。
- 稳态对比统一采用 `warmup=3, repeats=8`。8 次计时使用不同的预分配输入槽；计时前触碰全部槽，计时内保留每次输出（训练还保留 13 组梯度），最后同步。这样不会只执行 Jittor lazy 图的最后一个输出。
- `fwd_bwd` 使用随机上游梯度和 `autograd.grad`，脚本检查 13 组梯度全部 finite 且非零；不含 optimizer、grad clip 或参数更新。
- Jittor 的 `default` 在当前 fp32/训练条件下实际走 SDPA math fallback。PyTorch `default` 允许自动选择优化后端；`math` 用 `SDPBackend.MATH` 强制 math，二者不可混写。

## 性能结果

以下 ratio 均为 `Jittor / PyTorch`，小于 1 表示 Jittor 更快。

| dtype / phase | Jittor default | PyTorch default | ratio | PyTorch forced math | ratio |
| --- | ---: | ---: | ---: | ---: | ---: |
| fp32 TF32 on / forward | 0.7006 ms | 0.2607 ms | 2.69x | 0.4667 ms | 1.50x |
| fp32 TF32 on / fwd+bwd | 1.5985 ms | 1.8279 ms | 0.87x | 2.8280 ms | 0.57x |
| fp32 TF32 off / fwd+bwd | 1.9077 ms | - | - | 1.6914 ms | 1.13x |
| fp16 / forward | 1.1538 ms | 未完成 | - | 未完成 | - |

结论受 phase 和 SDPA 后端显著影响：fp32 推理时 Jittor math fallback 比 PyTorch default 慢 2.69x，即使同为 math 仍慢 1.50x；但本 block 的 `fwd+bwd` 在 TF32-on 口径下快于 PyTorch，说明当前 Jittor lazy graph/反向融合能摊薄部分 backward 开销。关闭 TF32并强制同为 math 后，Jittor 则慢 1.13x。该反转需要在真实 HF model、optimizer step 和多轮训练中复核，不能外推为 Transformers 端到端训练已经更快。

## 精度

使用 TF32 off、PyTorch forced-math 的同输入 NPZ 对拍，共 1 个 block 输出和 13 组梯度：

- 输出：`max_abs=0.32837`，按参考最大值归一 `3.80e-5`，`rel_l2=8.50e-6`。
- 梯度：最差按参考最大值归一误差 `4.90e-4`，最差 `rel_l2=3.66e-4`。
- 所有输出和梯度 finite，全部梯度非零；数值接近但不是逐位一致。

## 显存

在统一 8-slot、TF32-on 口径下，脚本记录的 peak allocator memory 为：forward Jittor `272.0 MiB`、PyTorch `246.2 MiB`（1.10x）；fwd+bwd Jittor `583.0 MiB`、PyTorch default `477.9 MiB`（1.22x）。Jittor 的 before/after 数值相同，而 PyTorch 在反向期间上升，因此这里只能视为该 harness 保留全部槽和输出时的工作集，不能当作单 block 的严格峰值显存结论。
