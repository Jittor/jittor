# 追踪 JIT 编译失败归属

## 操作

1. 构造包含一个确定错误 kernel 与一个合法 kernel 的小图；保留请求顺序与实际编译完成顺序不同的情况。
2. 在隔离缓存执行，保存生成源码、完整编译命令、退出码和 stderr。确认错误关联实际失败任务，
   不能从最后一个调度的算子或共享临时变量推断归属。
3. 分别覆盖串行与受控并行编译、生成失败、编译失败和加载失败，验证异常保留原始原因与上下文。
4. 合法分支应仍可单独编译运行，热缓存行为也需覆盖。不能因全局短路而“正确地”永远报错。
5. 保留失败源码与日志在 lab，不在源码目录生成报告。不要用宽泛异常捕获把失败变成 skip 或成功。

维护中的入口在 `tests/build/`、`tests/codegen/`；使用 `rg` 查对应编译器测试再扩展最小复现。
若错误只在首次升级 JIT 工具时出现，先确认维护入口的特定重试协议，不吞掉一般编译错误。
