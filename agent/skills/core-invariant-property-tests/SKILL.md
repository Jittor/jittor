# 测试图与执行器不变量

## 选择不变量

用小型合成图覆盖链、分叉、汇合、控制依赖、共享 view 和删除顺序，而非只跑一个大模型。
每条属性明确作用阶段：构图、编译、执行、释放或查询。期望值从独立关系计算，不调用被测
实现生成自己的答案。

- 存活数、分配数和遍历次数使用前后增量；进程全局绝对值会被其它测试污染。
- 输入与输出的生命周期分别覆盖，保留别名时验证读写及最终释放；加入不共享内存的阴性对照。
- 嵌套遍历应保持外层标记，查询若声称无遍历则检查 `TraversalEpoch` / `tflag_count` 没有增长。
- 结构扫描要求命中非空集合。已知缺陷的 xfail 应精确限定触发条件并使用 strict，不能宽泛吞异常。

## 从图反推改为显式记录

在关系产生的位置写入事实，而非在查询时从算子名或图形状猜测。
明确记录的所有者、更新时间、失效点及对象释放后的行为；不要只把昂贵遍历换成不会失效的缓存。

验证 view 与非 view、重绑定、复制、停止梯度、优化器更新和生命周期交错；同一查询要与实际
行为交叉验证。记录字段不能无意强持有整张图，销毁后的存活增量必须恢复。

原生 C++ 属性用 `src/tests/` 的 JIT 测试入口，Python 行为用 `tests/core/`，
namespace/源码归属用 `tests/structure/`；不要用结构检查代替真实执行。
