# 验证纯搬移重构

## 操作

1. 冻结源文件后，在 lab 留下基线 SHA、完整 diff 与文件映射，包括新增、删除和未跟踪的任务文件。
2. 为搬移单元建立旧位置到新位置的对应关系，比较函数体、默认参数、装饰器、宏条件和注册顺序。
   只允许明确的导入/命名空间适配；文本归一化结果相同不等于语义相同。
3. 特别检查 Python 的 import 副作用、循环依赖、公开对象身份、pickle 模块名；C++ 的静态对象
   初始化、链接可见性和宏作用域。不要因“只是移动”跳过这些差异。
4. 同步入口、打包清单和调用路径。对外路径需要保留兼容时，用薄转发并测试身份或行为。
5. 运行受影响测试和结构门禁；对比两轮 nodeid/结论，不能以候选少跑换取绿色。

基线在独立 worktree 验证，不把旧文件复制回共享工作树覆盖新修改。
若发现必须修逻辑，将其明确列为行为变更并增加定向回归，不再声称纯搬移。
