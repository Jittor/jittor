# 证明实际选择了 CUDA 后端策略

## 证据链

1. 固定输入、形状、dtype 与实际设备，记录有效选项和配置来源。先跑正确性参考。
2. 追踪选项从 Python 到缓存键、编译参数及实际库调用的传递；修改选项应生成不同键或明确复用。
3. 从实际加载的产物、库日志或 profiler 证明命中目标算法/精度路径。
   flag 值正确不代表后端使用了它，单个耗时差也不是命中证据。
4. 在不同进程或独立 worktree 做 A/B，复用相同 fixture、预热和计时口径；
   不用 `git checkout HEAD --` 覆盖工作树来模拟关闭补丁。
5. 检查 fallback 与负向输入。没有目标能力时应符合契约地拒绝或明确降级，不能把 CPU 结果标为 CUDA。

精度变化要报告前向、梯度和训练更新误差；默认精度修改不是单纯性能重构。
缓存行为需覆盖热复用与选项切换，测量方法见[性能分析](../jittor-performance-profiling/SKILL.md)。
