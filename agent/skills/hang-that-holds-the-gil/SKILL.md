# 定位持有 GIL 的挂死

## 定位

用本任务 PID 收集 Python/C++ 栈、线程状态和等待对象。Python 的计时线程无法在 GIL 被长期
持有时充当可靠 watchdog；用外部进程设截止时间并保留退出证据。先区分正在编译、等待编译锁、
等 peer、等设备和锁环，不因 CPU 为零就认定死锁。

## 修改与验证

- 只有无需 Python API 的阻塞区间才能释放 GIL；确认对象引用与 C++ 所有权在等待中仍有效。
- 回到 Python 或构造异常之前重新取得 GIL。不要持有另一个会被回调请求的锁跨越等待。
- 为 peer/资源等待提供有界失败及清理路径；取消后 worker 必须实际结束。
- 复现放 `tests/_helpers/child_process.py` 等受控子进程，覆盖正常完成、超时和失败，
  另外验证 Python 线程能继续前进，不能只把超时改长。

不通过删除活跃缓存或批量终止同名进程“修复”挂死；清理限定于本任务的进程与状态目录。
